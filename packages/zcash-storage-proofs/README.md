# zcash-storage-proofs

Typed codecs, schema validation and explicit native witness preparation for the
`ironwood` and `ironwood_aztec` Noir circuits (Ironwood V3 notes, V6 transactions,
NU6.3, Aztec 6.0.0). Node 22 or newer.

Importing the package writes no files, launches no process and contacts no network.
A prepared result records `checkpointAuthorized: false` and `proofVerified: false`:
preparation is not verification. The matching Noir relation checks every prepared
value under a checkpoint the application authenticates. What each claim proves and
the application's duties are in
[docs/API.md](https://github.com/iAmMichaelConnor/zcash-storage-proofs/blob/main/docs/API.md#consumer-obligations).

| Export | Contents |
| --- | --- |
| `.` | Envelope validation and preparation (`prepareContents`, `prepareInclusion`, `prepareNullifierInclusion`, `prepareMemoCreatedInBlock`, `prepareRawBlocks`, `fetchCompleteBlocks`, `prepareNullifierAbsence`), raw transaction and block inspection, `PreparationError` |
| `./aztec` | `installCapsules`, `installClaims`: checked capsule transport into an Aztec PXE |
| `./native` | `createNativeHintProvider`, `prepareContentsWithNative`: Sinsemilla hint capsules from an explicit native executable |
| `./toolchain` | `runTool`, `verifyTool`, `ToolExecutionError`: pinned execution of an external tool |
| `./profiles` | Capacity profiles: `listProfiles`, `getProfile`, `inspectBlocks`, `assertProfileFits` |
| `./schemas/*` | JSON Schemas of the envelopes |

The package is not published to npm. Build it from a checkout and install the
tarball (see the [repository README](https://github.com/iAmMichaelConnor/zcash-storage-proofs#typescript-sdk)).

## Envelopes

Every envelope has `schemaVersion: 1`, a `kind` and `{pool: "ironwood-v3", era:
"nu6.3", network}`; unknown fields and versions reject. The JSON Schemas in
`src/schemas/` (generated by `scripts/host_schemas.py`) are structural; the
TypeScript validators also enforce bounds, hash relations, curve membership and
coverage. A checkpoint is `{height, hashLE, policyId}`: `hashLE` is the raw SHA256d
digest (use `rpcHashToLE` for display hashes) and `policyId` names, but does not
establish, the application's policy (`CheckpointPolicy.authorize`).

| Envelope | Required data | Result |
| --- | --- | --- |
| `contents` | Note opening, 32-level path, header, history node, auth root | Capsules 60/61 |
| `action-inclusion` | V6 effect digest inputs, header, transaction path, index, count, Action index | Capsule 68 |
| `created-in-block` | Action inclusion plus key-free opening | Capsules 68/69 |
| `complete-blocks` | Every transaction of consecutive blocks, headers, checkpoint | Validated scan input |
| `raw-blocks` | Raw bytes of consecutive blocks | A `complete-blocks` envelope |
| `prepared-witness` | Result, arguments, expected claims, unverified status | Transportable output |
| `capsules` | Address/slot/scope/field records | Validated capsule payload |

Openings hold `receiver.g_d`, `receiver.pk_d`, `value` (decimal u64), `rho` and
`rseedHex`; coordinates and rho are three canonical decimal limbs of 120/120/15
bits and receivers are nonidentity on-curve points. No key or authority belongs
there. Paths are a u32 position and 32 bottom-up siblings. Addresses are canonical
decimals or the SDK's 32-byte `0x` form (normalized to decimal), fields and amounts
decimal strings, and bytes lowercase hex without `0x`. Effect data uses Noir's
snake_case names with actual-length arrays. Wallet backups, lightwalletd compact
blocks and wallet interchange formats are not accepted directly; a compact block
lacks the opening data.

## Capsules

The slot layouts are defined in
[docs/API.md](https://github.com/iAmMichaelConnor/zcash-storage-proofs/blob/main/docs/API.md#capsule-slots);
`src/slots.ts` (`SLOTS`) holds the same values, and `claimSlot` gives the slot of
claim `k` at one address (`slot + 256 k`).

`installClaims([{prepared, targetAddress, claim}], transport, policy)` checks each
witness, moves it to its claim's slots and rejects collisions before writing
anything; scans take claim 0 only. The host prepares no authority capsule, and
`installCapsules` rejects the secret authority slots 64 and 65.

`installCapsules` and `authorizePrepared` check a copy taken before any `await`: a
known claim with its exact slot set (`CLAIMS` in `src/prepare.ts`),
checkpoint-bound arguments strictly equal to values re-derived from the checkpoint,
correctly typed free arguments, and SHA256d of the slot 60 or 68 header equal to
`checkpoint.hashLE`. The policy gets frozen copies, only checked capsules are
installed, and the returned arguments are re-derived, never the caller's objects.
These are defence in depth; native hints, the memo payload and scan windows are
left to the circuit, which must still enforce the checkpoint.

## Preparation functions

- `prepareContents` checks representation, coordinates, lengths, header/history
  commitments and checkpoint binding; the circuit checks the commitment and
  membership. The `native` export's `prepareContentsWithNative` and
  `createNativeHintProvider` (explicit executable, SHA-256 pin, work directory) add
  native hint capsules with `includeHintCapsules: true`. The host checks only the
  provider output's shape, that the note-hash point is on the curve and that its
  Merkle root equals the header's root; it does not recompute the hash, root or
  records. So `expected.cmxLE` is `"native-provider-unverified"`: never use it for
  indexing or replay before the circuit returns the authoritative cmx.
- `prepareInclusion` prepares a selected Action or created-in-block claim; its
  `actions` parameter is the capacity (larger transactions fail with
  `PROFILE_ACTION_CAPACITY`) and `expected.actionCount` / `actionCapacity` record
  both. `prepareNullifierInclusion` prepares slot 68 for
  `ironwood_aztec::creation::inclusion::<4, 32>` with the nullifier as `expected_nf`.
- `prepareMemoCreatedInBlock({inclusion, rawReceiverHex, memoHex, actions}, {contractAddress, actions, depth})`
  takes the 43-byte raw receiver (not Unified Address text), the 512-byte memo and
  every full Action ciphertext in order (`encrypted_note` 580, `value_commitment`
  32, `randomized_key` 32, `outgoing_ciphertext` 80 bytes). It reports
  `memoEncryptionChecked: false` and `rawReceiverChecked: false`.
- `prepareRawBlocks` parses raw blocks; `fetchCompleteBlocks` uses an injected
  read-only RPC client, a start height, checkpoint and maximum count, and checks
  the transaction trees, links and tip. `inspectRawTransaction` / `inspectRawBlock`
  also read V4/V5 data without asserting validity.
- `prepareNullifierAbsence` takes complete blocks, a profile ID, nullifier and
  address. It rejects overflow, unsupported versions, a present nullifier, a first
  parent other than the pinned predecessor (`NULLIFIER_ABSENCE_PREDECESSOR`), a
  testnet tip above 4,465,025 (`NULLIFIER_ABSENCE_EPOCH`) and a noncanonical
  nullifier (`NONCANONICAL_NULLIFIER`; never reduce modulo p). It writes slot 63,
  66 or 67. Stateful extensions take a prior height and return
  `authenticatedPriorStateRequired`. Unreleased profiles need
  `allowExperimentalProfile`.

Errors carry a stable `PreparationError.code` and `.path`.

## Command line and external tools

`ironwood-prepare doctor | prepare | prepare-nullifier-absence` (`bin/ironwood-prepare.mjs`)
writes mode-0600 output and never overwrites.

The `toolchain` export's `runTool` requires an absolute, non-symlink, not
group/world-writable regular file, hashes the bytes it read, copies them into a
fresh private directory (`toolDirectory` must allow execution) and runs the copy
with a minimal environment (`PATH`, `HOME`, `TMPDIR`, `LANG`, `LC_ALL`, `TZ` plus
the caller's `env`, always without `LD_*`/`DYLD_*`). The pin covers only that file,
not a `#!` interpreter or shared libraries, and the tool sees the private opening.
Failures throw `ToolExecutionError` with bounded output.

The native hint tool for `createNativeHintProvider` is the Rust program in
`src/native/` (zcash/orchard, sinsemilla and pasta_curves; not shipped in the npm
package). Build it with the pinned toolchain and pass the binary and its SHA-256
explicitly:

```sh
cd src/native
cargo build --release --locked --target-dir /abs/fresh
sha256sum /abs/fresh/release/ironwood-native-hints
```

## Capacity profiles

`profiles/catalogue.v1.json` binds each nullifier-absence and contents profile to
its source package, compiler, artifact interface, constrained bytecode and measured
gate count (verification keys are null). `src/profile-catalogue.ts` is generated
from it (`npm run catalogue`; `npm run catalogue:check` compares). **No profile is
currently selectable**: every binding names a source graph that differs from the
current source, so ordinary preparation rejects it until it is validated and
released again.

```ts
import { inspectBlocks, getProfile, assertProfileFits } from 'zcash-storage-proofs/profiles';
assertProfileFits(getProfile('nullifier-absence-2b-4t-2a-256r-v1'), inspectBlocks(completeBlocksEnvelope));
```

Stateless block counts are exact; a one-block input is never padded into a
two-block proof. The scan circuits do not constrain inactive rows and blocks, V4
rows' effect fields or the unhashed fields of V5 and zero-Action V6 rows, so the
host's zero padding is a convention: many capsules encode one statement, and
consumers must not hash or deduplicate scan capsule bytes.

## Development

From this directory:

```sh
npm ci --ignore-scripts --no-audit --no-fund
npm run build            # tsc into dist/
npm run typecheck
npm test                 # build, then node --test tests/*.test.mjs
npm run test:package     # npm pack, offline install into a scratch consumer, typecheck and import
npm run fixtures:check   # tests/fixtures match their generator
npm run catalogue:check  # src/profile-catalogue.ts matches profiles/catalogue.v1.json
npm run schemas:check    # src/schemas/ match scripts/host_schemas.py (`npm run schemas` rewrites)
```

The tests need no network, Zcash node, nargo, proof or Aztec PXE. `npm pack` runs
`scripts/package-assets.py`, which stages `LICENSE`, `NOTICE` and `docs/*.md` from
the repository root into the package.

`tests/prepare-fixtures.py` (`npm run fixtures`) writes the contents,
created-in-block, memo and scan fixtures in `tests/fixtures/` from the repository's
committed native fixtures (`fixtures/`) and its Python fixture modules (`scripts/`).
Headers, history paths and the outer transactions of these fixtures are synthetic.
Two kinds of file are retained, not generated: `raw-v6-transfer.json`, the raw
transaction of the retained transfer in `fixtures/ironwood_transfer`, which the
script checks against its hash and the bundle's effects; and the public parser
vectors (mainnet block 1,687,106 and ZIP 244 vectors), whose sources and hashes are
in `tests/fixtures/public-source-manifest.json`.
